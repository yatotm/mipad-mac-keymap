# 按键与触控板同时操作的停顿

2026-09-26，Moonlight 模块 0.2.6。用户反馈：持续移动触控板时按任意键，箭头暂时停止；过一会自动恢复到手指已经移动到的位置，不需要重新落指。

## 已确认

- 采样时实际使用触点连接：`Xiaomi Keyboard` 与 `Xiaomi Touch`。同时采集原始输入、Moonlight 接收/发送计数和本地光标绘制计数，不记录字符。
- 原始触点帧在按键期间已经停止；不是仅光标绘制停止。代表样本：按下约在 29380.1 秒、松开约 29380.3 秒，触点帧约在 29380.8 秒恢复；另一组松开约在 29381.5 秒、29382.0 秒恢复。100 毫秒统计窗口限制了这些数值的精度。
- 同一期间应用 `receiving=true`、`captured=true`，取消计数为 0。应用事件和本地箭头随底层报告恢复，因此保持手指接触时会跳到新的位置。
- 设备使用 Nanosic SDK 1.3.3 的触点输入链路；HID 接口经 `nanosic_driver` 与 `hid-multitouch` 上报。当前证据将暂停定位到 Android 应用收到事件之前的底层路径，尚不能仅据此精确区分控制器固件和驱动中的具体分支。
- 常规 Android 手掌过滤在设备转储中为关闭。AOSP Android 15 的捕获模式直接走原始触点转换，不能把未捕获模式的 `Keyboard Palm Prevent Timeout` 参数直接当作本问题的开关。

- 同一客户端与 Mac 后端下，用户确认 **蓝牙模式正常**，可以同时移动和按键。

## 修复边界

本次没有找到明确、已核实的运行时开关。查到的公开同名驱动缓存使用另一种定时语义，不能据同名函数便改写内核。未刷写内核、替换驱动、发送未知固件命令或全局关闭系统过滤。

因此当前仍保留此问题，不能宣称已经修复。迁移 ADB 输入到 Moonlight/Sunshine 会解决网络依赖，但不能自动补出此段未送达应用的实时触点。用户随后实际切换到蓝牙并确认正常，已将问题范围缩到触点连接链路。当前可用的绕开方式是使用蓝牙连接；触点模式的半秒抑制仍未修复，后续需核对 Nanosic 控制接口，不能用预测位移或延后回放掩盖停顿。

当前 0.2.6 的右击和光标大小已获得用户正常反馈。并发按键必须作为后续输入迁移的独立验收项，不能被普通打字、单独移动鼠标或连接成功替代。

临时采样结束后删除原始记录和拉取的诊断文件，只保留以上结论。未发布平板系统框架或驱动二进制。
